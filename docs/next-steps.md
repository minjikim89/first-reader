# Deferred: prose the system does not read yet

Reading free-text decline reasons and writing the reviewer's note are done. Four
things were designed alongside them and cut for the deadline. They are listed
here with what each would take, so picking one up does not start from scratch.

Each has the same shape as the two that shipped: an estimate, marked as one,
beside a fact it never overwrites, correctable by a reviewer through the same
`Transform` path.

## 1. AfC comments

`{{AfC comment|1=...}}` is where reviewers write what they actually want, and it
is usually far more specific than the code beside it. One real example:

> You'll need to '''completely''' rewrite the article from scratch if it was
> generated by an LLM. See [[WP:LLM]].

Two things to pull out: what the reviewer asked for, and whether it agrees with
the standing blocker. **A comment that points somewhere else is a disagreement
between two reviewers, and that is a strong escalation signal** — it belongs in
`AdvantageState.INCONSISTENT_REVIEWERS`, which currently only detects
disagreement from the codes.

Cost: needs the current wikitext, so one extra API call per draft.
`first_reader.wiki.WikiClient.get_wikitext` already caches.

## 2. Edit summaries

"made changes re wrote organically", "have re- written completely". A diff says
how much changed; it cannot say what the contributor thought they were fixing.
That is the one place `AttemptSignal` is blind — it carries the summaries as
strings and reads none of them.

Needs no extra fetch; the summaries are already on the card.

## 3. Wording the learned rules

`policy.relax_sentence` and `policy.tighten_sentence` are f-string templates.
Turning a decision history into a sentence a reviewer can argue with is the
mechanism the whole policy design rests on, and a template does it woodenly.
Keep the templates as the fallback: a rule nobody can read is not a policy, so a
failed generation must never leave one unworded.

## 4. Narrating the escalation

`EscalationJudgment.reason` currently reads as arithmetic plus a state name.
A reviewer wants a sentence about what they would see here that the tool could
not settle. The arithmetic should stay and be accompanied, never replaced.

## What every one of them must keep

- The deterministic path decides. `family`, `fixable_by_rewrite`, the escalation
  inequality and attempt detection are not model outputs and must not become them.
- No new decline codes, ever. A reading places prose in one of three existing
  families, or says it cannot tell.
- Every reading quotes its source verbatim, and the quote is checked against the
  source before the reading is kept.
- Failure is silence. No key, no network, a bad response — the deterministic
  path continues and the template writes the note.
- One cheap call per draft per feature, with `limits` on the invocation. Never
  `Guide` on `after_model_call`: the framework imposes no retry cap.
